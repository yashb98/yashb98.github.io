The win that wasn't

Response-masked fine-tuning looked like a 0.68 perplexity win with a very tight interval. The two arms had been scored on different tokens. On one fixed held-out set the gap fell to 0.009, and a full-sequence check flipped its sign.

Read how it collapsed

A null called in advance

I pre-registered that GRPO wouldn't help at this size, because the base model solves about 1% of maths problems. After 300 steps it scored 1.0% on GSM8K against 1.12% for the fine-tuned floor, and it didn't beat a random-reward control. This run used a single seed, as registered.

Inside a GB10 fix

New GPUs expose assumptions that older ones never tested. Here's one bug from my GB10, from failure to merged fix in PyTorch Helion.

A test fails with an out-of-resources error

test_scaled_mm failed on my GB10 before a single kernel could run.

OutOfResources: out of resource: shared memory,
Required: 147456, Hardware limit: 101376.
GB10 limit, 101,376 bytes
Needed147,456 bytes

The GPU borrowed a config from an older chip

GB10 had no heuristic file of its own, so the loader fell back to the sm90 file, whose configs were tuned on H100 with 227 KB of shared memory per block. The test checked for FP8 support but not for shared memory, so it ran a config that could never launch.

Two changes

First, I guarded the test with the existing shared-memory check at 147,456 bytes, so it skips on smaller GPUs, GB10 included, and H100-class hardware still runs it.

Second, I generated an sm121 heuristic file on the GB10 for the two test shapes. One config covers both, at most 1.02× slower than the best per-shape config, and it fits the limit. This was a correctness fix, tuned quickly on two shapes, not a full performance pretune.

The suite goes from 2 failures to 0

Before, on GB10
2 failed
After, on GB10, with the test skipped
0 failed
New heuristic against fp32, run with the guard bypassed
0.0 max error

It merged on 20 August 2026. The wider problem is in Helion #4097, in review: on a GB10 with only the sm90 file, 19 of 24 decode shapes failed at first launch.

Interpretability

Reproducing a paper turned into co-authoring its revision

I reproduced the central result of Evan Duan's paper on steering side effects in sparse autoencoders. On GPT-2-small, decoder crowding predicted downstream collateral at a Spearman of 0.482 [0.381, 0.571], against the published 0.466. My first notebook scored 0.548 before I removed contexts ending in padding.

The paper hadn't controlled its collateral labels for firing frequency, so I ran that control across all four of its model and SAE settings. I'm now co-authoring the revision.
